# 多个人格 · 独立索引（实施计划）

**日期**：2026-10-31（晚上开新对话照这份做）
**决策人**：主人（2026-10-31 17:49）
**结论先行**：这是**产品化需求**，不是本机特例。很多人的 DSH 里有多个人格，共用一个索引会让不同人格互相检索到对方的内容——必须按人格隔离。

## 一、现状（2026-10-31 已完成的部分）

- 插件 `dsh-semantic-recall` v0.2.0，**单索引**：`$DSH_HOME/session-recall/index/{meta.json,vectors.f32}`
- 工具注册在 profile 根上 ⇒ **所有 agent 都能看到** `session_recall`
- 已做**临时隔离闸门**：配置 `allowFromWorkspaces`（逗号分隔的目录名子串）
  - 本机设成 `deepseek/zefeila`，饭饭（`H:\deepseek\fanfan`）调用会被拒
  - 实现：`workingDirectory.ensure(exec.agent)` 拿调用方 cwd，见 `index.js` 的 `callerDir()`
  - 缺点：只是**拒绝**，不是**分开**。饭饭自己也没有可用的历史检索。

## 二、目标

1. 每个人格只检索**自己的会话**，互相看不到
2. 没有归属的会话有明确去处（默认库或按配置）
3. 设置页能看到每个人格各建了多少块、什么时候建的
4. 保持现有对外行为不变（单人格用户无感）

## 三、设计（建议方案）

### 作用域定义
新增配置 `personas`（JSON 或分号分隔），每项：

```
名字 | 匹配规则（目录名子串，逗号分隔）
泽菲拉 | H-deepseek-zefeila
饭饭   | H-deepseek-fanfan
```

### 索引分库
```
$DSH_HOME/session-recall/
  scopes/
    <persona-key>/index/{meta.json,vectors.f32}
    default/index/...          # 不属于任何人格的会话
```

- 抽取时按**会话所在工作区**分类：命中某个 persona 的规则 → 进那个库；否则进 default
- 建索引/增量时**每个库独立**跑（可以串行，量不大）
- `meta.json` 里记 `scope` 与 `sourceWorkspaces`

### 查询路由
- 用 `callerDir(exec)` 判断调用方归属哪个 persona
- 命中 → 只在该库检索
- 调用方不属于任何 persona → 只查 `default` 库（**绝不跨库**）
- 保留 `allowFromWorkspaces` 作为兜底白名单（两者取交集）

### 设置页
- 新增「人格」区块：列出每个 persona、块数、建于何时、「重建这一库」按钮
- 人格配置的编辑：先做只读展示 + 通过 `session_recall_config` 改 `personas` 字符串（UI 编辑留到下一版）

## 四、迁移

## 六、坑（都踩过，别再来一遍）

1. **`ctx.settings.update()` 在 0.2.1-rc.5 不落盘** ⇒ 权威配置是 `config.json`，设置页走自己的 `/api/session-recall/*`
2. 改 `cordis.patch.yml` 的 config **不热更新**，必须 remove_bundle + install（或重启）
3. 客户端 bundle 改动后**必须刷新页面**才注入
4. `ToolRunContext` 里拿 cwd 用 `workingDirectory.ensure(exec.agent)`；拿不到时**fail-open**（否则自己先用不了），但要打日志
5. 嵌入 provider 变更会让所有库的向量作废 ⇒ 版本记在各自 meta 里，按库判断
