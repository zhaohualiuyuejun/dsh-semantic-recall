# 二期验收报告 · 多源分库

**日期**：2026-10-31
**范围**：`dsh-session-recall`（会话语义检索）二期 —— 多源 + 分库
**结论**：**通过**。每个源一个独立库，源间互斥、单源可含任意工作区；旧单库保留作回退。

---

## 一、设计定稿（2026-10-31 20:30 主人批准）

> 「互斥是**源与源之间**的事；单个源本来就该能勾选任意工作区。」

- **一个工作区只能归一个源**（后出现的源不能抢已归属的，`parseSources` 强制互斥）
- **一个源可以包含任意多个工作区**（包括全部）
- **一个源 = 一个独立库**：`$DSH_HOME/session-recall/scopes/<源id>/index/`
- **查询路由**：调用方工作区属于哪个源 → 查哪个库；不属于任何源 → 拒绝
- **没有源** = 老行为：全部工作区共用一个库（`index/`）

## 三、数据模型

```json
[
  {"id":"src1","name":"泽菲拉","workspaces":["--H-deepseek-zefeila--","--C-Users-ASUS-.dsh-dsh_wechat--"]},
  {"id":"src2","name":"饭饭","workspaces":["--H-deepseek-fanfan--"]}

```
- 空源合法（新建后还没勾）；空源不建索引
- 源 id 会清洗成安全目录名（只留 `[A-Za-z0-9._-]`）

## 五、迁移与回退

**迁移**：首次检测到"有源 + 旧库存在 + 该源还没有库" ⇒ 把 `index/` **复制**到 `scopes/<第一个源>/`。
**旧库不删**——移除所有源后立刻回到旧库，无需重建。

**回退**：恢复 `.backup/2026-10-31-phase2/` 下的文件，并删除 `lib/` 下新增的 scope 参数即可；
或把 `config.json` 的 `sources` 清空（回到老单库，旧库完好）。

## 六、修复（2026-10-31 21:00）：源改名回跳 + Key 澄清

**症状**：源名改成「饭饭」，失焦后跳回「新源」。
**根因**：输入框 `onChange` 直接改本地 cfg 的 name，`onBlur` 时 `clean === src.name` 判成"没改"→ 跳过保存；3 秒轮询从服务端拉回旧名。
**修法**：源名用**独立草稿 state**；onChange 只改草稿，onBlur 才比对保存。
**同期**：API Key 保存后清空是设计（留空=不改），提示已写明确；接口地址一般留空（内置默认）。实测 Key 可用（4096 维）。
**验收**：客户端渲染 **13/13**。

## 六·五、对外锚点与下钻协议（2026-10-31 21:30）

**目的**：让「记忆插件 → 原文」能自动接上。不抢生态位，做可组合的零件。

**新增锚点**（真实索引实测覆盖率 **100%**，2841/2841）：
- `session`：会话 id（= `$DSH_HOME/sessions/<工作区>/` 下的目录名）
- `hits[].messageId`：user 消息取 `data.id`，assistant 消息取 `data.message.id`
- `hits[].seq`：消息顶层的 `seq`

**新增下钻入口**：`session_recall({ session })` ⇒ 跳过语义检索，直接返回该会话原文（按时间排序；`max_sessions` 默认 20、上限 50）。

**验收**：`tools/verify-anchors.mjs` **7/7**；真实索引 2841 块 100% 带 `messageId`/`seq`；subagent 下钻实测通过。

**成本**：**零重嵌**——旧向量全部复用，只刷新块对象（`indexer` 的 `kept` 分支天然支持）。

## 七、已知限制

1. 源之间共用的仍是**同一套嵌入配置**（provider / model / Key 全局）——理由：向量可比性 + 一把钥匙。每源的**工作区集合**是独立的。
2. 删除源不会删它的库（保留在 `scopes/` 下，方便恢复）；需要回收空间时手动删。
3. 旧库与新库各占约 40MB（迁移期双份）；确认稳定后可删旧库。
